# 0.0.61

- Date: 2026-10-11
- Bookmark: samw/ai/perf-fixes
- Components: cli

## Summary

Frontmatter lines are split with plain string code instead of a regular expression, so `list`,
`search`, and `lint` are about twice as fast in a large repo.

## Changes

- New `parseField` in `cmd/sisyphus/document.go` splits a frontmatter line into its key, value, and
  inline comment. `document.get`, `document.set`, and the read checks of `issueProblems` use it.
  Before, each of them ran the regular expression `fieldPattern`, which was about 45% of `list` at
  20,000 issues.
- The result does not change. A test compares `parseField` with the old regular expression on every
  line of the template, known edge cases, and 200,000 random lines of keys, quotes, escapes, `#`,
  brackets, and non-ASCII text. On a generated repo of 20,000 issues, the old and the new binary
  print the same `list --json`, `search --json`, and warnings, and the same `lint --json` on 5,000
  issues apart from the cycle format of [[0.0.59]].

| 20,000 generated issues | Before | After |
|---|---|---|
| `list` | 815 ms | 395 ms |
| `list --ready` | 884 ms | 413 ms |
| `search` | 853 ms | 459 ms |
| `list --json` (all states) | 992 ms | 467 ms |
| `lint` | 1,949 ms ([[0.0.59]]) | 1,423 ms |
