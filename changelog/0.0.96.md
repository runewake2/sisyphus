# 0.0.96

- Date: 2026-10-11
- Bookmark: samw/ai/ux-fixes
- Components: sisyphus-mcp, docs

## Summary

sisyphus-mcp stops a `sisyphus` run when the client cancels the call, and when the run takes longer
than a time limit. Before, a run that did not end kept the call open for ever, and a cancelled run
continued.

## Changes

- Each run uses the context of the call, so a cancel from the client stops it.
- Each run stops after 60 seconds, with an error that tells the command and the limit.
  `SISYPHUS_MCP_TIMEOUT` (a duration such as `90s` or `2m`) changes the limit. An invalid value is
  logged, and the default applies.
- A child of `sisyphus` that keeps the output open cannot keep the call open: sisyphus-mcp waits
  for it at most one second after `sisyphus` stops.
- Tests use a fake slow `sisyphus` for the limit and for a cancel. [[sisyphus-mcp]] describes the
  limit, and its troubleshooting table has a row for it.
