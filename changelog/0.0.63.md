# 0.0.63

- Date: 2026-10-11
- Bookmark: samw/ai/perf-fixes
- Components: cli

## Summary

Commands that read many issues read the files on a bounded pool of goroutines, so `list`, `search`,
and `graph` are about 1.6 times as fast in a large repo.

## Changes

- New `issueIndex.preload` reads the files of many issues that a command has not read yet, with at
  most `GOMAXPROCS` workers and never more than 16, and keeps them in the same caches as `document` and
  `header`. Each file is still read once. Fewer than 32 files are read one at a time, where starting
  the workers would cost more.
- `matchingIssues` (`list`, `search`, `graph`), `lint`, the parent scan of `list --ready`, and
  `subIssues` and `dependents` (closing an issue) preload their issues.
- The test hook that counts reads is called under a mutex. A new test with 61 issues checks that
  `list --ready`, `search`, `lint`, and closing an epic read each file once and see every issue. The
  tests pass with the race detector.
- On a generated repo of 20,000 issues, `list --json`, `search --json`, and the warnings are the same
  as before.

| 20,000 generated issues | Before | After |
|---|---|---|
| `list` | 414 ms | 243 ms |
| `list --ready` | 424 ms | 285 ms |
| `search` | 456 ms | 297 ms |
| `graph <epic> --json` | 460 ms | 259 ms |
| `lint` | 1,481 ms | 1,226 ms |
