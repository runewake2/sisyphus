## Summary

`sisyphus graph --state` draws only the issues in the given states, so that a large graph can show
only the work that remains, for example with `--state open,in-progress`.

## Changes

- `graph --state` takes states, comma-separated, or `all` (the default). `<name>` and missing
  issues are always drawn.
- A chain of sub-issue links through left-out issues becomes one arrow, and so does a chain of
  dependency links through left-out issues that are not closed. Other chains are not drawn. The
  JSON of a joined edge has `through`.
- The legend, and a Mermaid comment, tell how many issues are left out; the JSON has `filtered`.
  Availability and the work path do not change.
- `sisyphus_graph` takes `state`.
- In this repo, the graph of [[large-repo-performance]] goes from 13 issues to 3 with
  `--state open,in-progress`.
- [[sisyphus-graph]] and [[output]] describe the filter. The decision is
  [[0028-join-graph-links-through-filtered-issues]].
