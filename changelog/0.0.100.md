# 0.0.100

- Date: 2026-10-11
- Bookmark: samw/ai/ux-fixes
- Components: sisyphus-mcp, cli, docs

## Summary

The descriptions of issue names no longer invite models to guess names. The `name` of the tools
that take an existing issue showed the nested example `web/auth/fix-login-bug`, and models invented
nested names. Models also used `sisyphus_slug` to find an existing issue.

## Changes

- The `name` of each tool that takes an existing issue is now "The exact name of an existing issue,
  as sisyphus_list or sisyphus_search returns it, for example fix-login-bug. Do not guess a name:
  search for the issue first." Other forms, for example `[[name]]`, still work.
- The `name` of `sisyphus_new` tells to leave it out, and that a directory before the name only
  groups files and is not the parent. Its `parent` names an existing issue.
- `sisyphus_slug` tells that it makes a name for a new issue, does not find an existing issue, and
  is rarely needed.
- The help of `new` and `slug`, [[sisyphus-new]], and [[sisyphus-slug]] say the same.
- A test checks that no tool has a nested name example, and the descriptions of slug and new.
