# 0.0.87

- Date: 2026-10-11
- Bookmark: samw/ai/ux-fixes
- Components: cli, sisyphus-mcp, docs

## Summary

`sisyphus start` and `update --owner` no longer take an issue in progress from its owner. Before,
they replaced the owner with no error, so a second agent could take the issue of the first, and
neither knew it.

## Changes

- A start of an issue in progress, or an `--owner` change of it, by a different owner fails with
  `Issue '<name>' is in progress, owned by <owner>. Select another issue, or to take it from <owner>, add --take.`
- `--take` on `start` and `update` changes the owner, with a warning that names the old owner.
- A start by the same owner changes nothing and succeeds, so an agent can repeat it.
- An issue in progress with no owner can get one without `--take`. Changes of other fields, a
  close, and a stop do not check the owner.
- `sisyphus_update` takes `take`.
- [[sisyphus-start]] and [[sisyphus-update]] describe the rules, and the decision is
  [[0022-refuse-to-take-a-claimed-issue]]. [[sisyphus-update]] names git next to jj.
