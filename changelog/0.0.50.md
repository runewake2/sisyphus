## Summary

`sisyphus init` refuses to make a tracker below a directory that already has one, unless
`--nested` is given.

## Changes

- `init` fails when a directory above `--dir` has `issues/TEMPLATE.md`, and names that directory.
  Before, `init` in a subdirectory made a second, empty tracker, and every command there then found
  it instead of the real one, so the issues seemed to be gone.
- New flag `init --nested` makes the second tracker on purpose. `sisyphus_init` has a `nested`
  argument.
- `init` again in the root of a tracker still works.
- [[sisyphus-init]] describes the rule.
