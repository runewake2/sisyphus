# 0.0.64

- Date: 2026-10-11
- Bookmark: samw/ai/perf-fixes
- Components: cli

## Summary

A command that gets an issue by its full name finds it without reading every state directory.
`show`, `update`, and `edit` of one issue take about 5 ms instead of about 40 ms at 20,000 issues.

## Changes

- `loadIndex` no longer walks the state directories. `issueIndex.walk` does it once, when a command
  first needs every issue (`all`), a shorter name, or a name in another case.
- New `issueIndex.exactOf` finds a full name with a `stat` of `issues/<state>/<name>.md` in each state
  directory, before the walk, for a valid (lowercase) name. It also finds a name that is in more than
  one state directory, which is still an error. `match`, `canonical`, `new`, and `lint` use it.
- A shorter name, closing an issue (which checks its sub-issues and dependents), and every command
  that lists issues still read the state directories, once.
- [[commands#Naming an issue]] says that a full name is the fastest form.
- Tests check that `show`, `update`, `edit`, and `remote` with a full name read no state directory,
  that a shorter name and a close still do, and that a full name in two state directories is still an
  error. The read-count test now allows a command to read a state directory at most once.

| 20,000 generated issues | Before | After |
|---|---|---|
| `show <full-name>` | 42 ms | 5 ms |
| `show <dir>/<full-name>` | 41 ms | 5 ms |
| `update <full-name> --priority low` | 43 ms | 5 ms |
| `edit <full-name> Notes x` | 39 ms | 6 ms |
| `show <bare name of a nested issue>` | 39 ms | 41 ms (walks, as before) |

## Notes

The fast path is only for valid names, which are lowercase, so that on a file system that ignores
case it cannot give a name in another case than the file.
