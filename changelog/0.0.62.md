# 0.0.62

- Date: 2026-10-11
- Bookmark: samw/ai/perf-fixes
- Components: cli

## Summary

Commands that use only the frontmatter of an issue read each file only up to the end of its
frontmatter. In a repo with long issue bodies, `list` and `graph` are about twice as fast.

## Changes

- New `loadHeader` in `cmd/sisyphus/document.go` reads a file up to the line that closes its
  frontmatter. It gives the same frontmatter, byte order mark, line endings, and errors as
  `loadDocument`. A document read this way has the flag `headerOnly`, and `save` refuses it, so that a
  partial read can never become a partial file.
- New `issueIndex.header` returns the full document when the command already read it, and otherwise
  a header. `list`, `list --ready`, `list --blocked`, `graph`, the scans of `update` and
  `depends-on`, and the issue checks of `lint` use it. `search`, `show`, `edit`, and the issue that
  `update` changes still read the whole file. Each command still reads each file once.
- Tests compare `loadHeader` with `loadDocument` (also with a BOM and CRLF), and check the errors and
  that a header cannot be saved.

| Generated repo | Command | Before | After |
|---|---|---|---|
| 20,000 issues, bodies of about 4 KB | `list` | 408 ms | 399 ms |
| 5,000 issues, bodies of about 40 KB | `list` | 249 ms | 109 ms |
| 5,000 issues, bodies of about 40 KB | `list --ready` | 250 ms | 105 ms |
| 5,000 issues, bodies of about 40 KB | `graph <epic> --json` | 302 ms | 115 ms |
| 5,000 issues, bodies of about 40 KB | `lint` | 2,150 ms | 1,913 ms |

## Notes

With short bodies, opening each file costs more than reading it, so the gain is small; it grows with
the length of the bodies. `lint` still reads every Markdown file in full for its link check.
