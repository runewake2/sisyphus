# 0.0.58

- Date: 2026-10-11
- Bookmark: samw/ai/perf-fixes
- Components: cli

## Summary

Wikilinks are resolved with maps instead of a scan of every file for each link. `sisyphus lint` at
20,000 issues takes 2.3 s instead of 39.4 s.

## Changes

- `repoCandidates` returns a `candidateSet`: the sorted files, a map from each lowercase key (a path
  from the root, with or without `.md`) to its files, a map from each part of a key after a `/` to
  the files whose key ends with it, and a map from path to file. `matchTarget` looks up both maps and
  keeps the sorted order of paths. Before, it compared each link with every file, so `lint` did about
  4 billion comparisons at 20,000 issues.
- A link to a heading in the same file (`[[#Heading]]`) finds its file with a map lookup.
- `links`, `resolve`, and `lint` give the same output as before. On a generated repo of 5,000 issues
  with missing, ambiguous, case-insensitive, non-Markdown, same-file, alias, and embed links, the old
  and the new binary print the same `lint --json`, `links --json`, and `resolve` output.
- A new test covers the order of `resolve --all` with exact and suffix matches.

| Repo | `lint` before | `lint` after |
|---|---|---|
| 20,000 generated issues | 39,392 ms | 2,291 ms |
