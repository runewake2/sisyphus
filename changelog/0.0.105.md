# 0.0.105

- Date: 2026-10-11
- Bookmark: samw/ai/ux-fixes
- Components: cli, sisyphus-mcp, docs

## Summary

New command [[sisyphus-rename]] renames an issue, or moves it to a directory, and changes every
link to it in the repo. Before, no command did this, and the docs said never to rename an issue.

## Changes

- `sisyphus rename <name> <new-name>` moves the file in its state directory (with `git mv` when git
  tracks it), and removes the directories that it leaves empty.
- Every wikilink that points to the issue changes: in other issues (also `parent`, `depends-on`, and
  `deferred-from`), in the issue itself, in changelogs, and in documents. Links in code do not. A
  link with only the file name stays so while the name is unique; other links and the frontmatter
  get the full name. Line endings stay as they are.
- The claim of the issue moves. An issue that another workspace has in progress is refused.
- `--dry-run` prints the move and each link that would change; `--json` with it prints the plan.
- `sisyphus_rename` runs it from MCP, with `dryRun`.
- [[commands#Naming an issue]], [[issue-format]], and CONTRIBUTING.md now tell how to move an
  issue, and recommend a move to a directory over a new file name. [[output]] has the plan shape.
  The decision is [[0027-rename-changes-every-link]].
