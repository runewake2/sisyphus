## Summary

sisyphus writes issue files atomically and holds a lock while a command changes issues. Before, a
command that read an issue while another command wrote it could see a part of the file, and two
changes of one issue at the same time could lose one of them.

## Changes

- An issue write goes to a temporary file that is then renamed over the issue file.
- Every command that changes issues holds one lock for the repo from its first read to its last
  write. The lock file is `sisyphus/lock` in the jj repo directory or the git common directory,
  which every workspace and worktree shares, or `issues/.lock` without jj or git. A command waits up
  to 10 seconds for it, and removes a lock that is older than 30 seconds.
- Of two starts of one issue at the same time, one succeeds and the other is refused.
- Tests run concurrent starts, concurrent appends, and reads during writes. Each test fails without
  the change.

  [[0023-lock-and-write-issues-atomically]].
