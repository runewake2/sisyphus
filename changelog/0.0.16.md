# 0.0.16

- Date: 2026-10-08
- Components: cli, mcp

## Summary

Draw `sisyphus graph` as a real dependency graph instead of a parent tree.

## Changes

- `sisyphus graph <name>` draws `<name>`, everything below it, and the path above it as boxes and
  arrows, and notes how many other linked issues are not drawn. Every arrow points from the issue
  that comes first: solid from a parent to a sub-issue, dotted from a dependency to the issue that
  depends on it. Below means sub-issues and dependents, all the way down; above means parents and
  dependencies, all the way up. `<name>` is marked with 📍, and a legend follows the drawing.
- Leaves are marked with 🍃: issues that are not closed and have no open dependency or
  sub-issue, so work on them can start now. In `--json`, a leaf node has `leaf: true`.
- On an epic this draws the whole epic. On an issue deep inside it, only that issue's part.
- New `--full` draws every issue linked to `<name>` by `parent` or `depends-on`, in either
  direction, including issues outside the parent tree.
- `--json` now prints `focus`, `nodes`, `edges`, and `hidden` instead of a nested tree. This changes the
  JSON format.
- New `--mermaid` prints the Mermaid flowchart source, which Obsidian and GitHub render.
- `sisyphus_graph` in `sisyphus-mcp` takes `full: true` and `mermaid: true`.
- The drawing uses `github.com/AlexanderGrooff/mermaid-ascii` (MIT license).

## Decisions

- The marks are emoji (📍 and 🍃) that always draw two columns wide, so boxes stay aligned. Emoji
  that need a variation selector are avoided, because terminals disagree on their width.
- An open sub-issue keeps its parent from being a leaf, as an open dependency does. Otherwise
  every epic without a `depends-on` would be marked ready to start.
- Arrows all flow one way, from epic to task to sub-task and from a dependency to what it unblocks.
- By default, draw what is below an issue and the path above it, not its siblings, so a deep issue
  shows only what it takes to get there. The whole linked family is one flag away.
- Left to right, because top down puts every sibling in one wide row.
- No ASCII mode: the library draws dotted edges as solid in ASCII, so the edge kinds would look
  the same.
