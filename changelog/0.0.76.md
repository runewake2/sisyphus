## Summary

New command `sisyphus open <name>` opens an issue in the editor of the user, and checks the file
after.

## Changes

- `open` finds the file of the issue in any state directory and subdirectory, and starts `$VISUAL`,
  or else `$EDITOR`, with its arguments (for example `code --wait`). Without either, it fails with a
  hint.
- When the editor exits, `open` checks the file with `issueProblems`, as `lint` does, and warns. It
  does not change the file.
- New page [[sisyphus-open]], listed in [[commands]]. Tests use a fake editor script for the edit,
  a warning after a broken edit, and a missing editor.
