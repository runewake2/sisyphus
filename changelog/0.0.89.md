## Summary

Agents in different jj workspaces or git worktrees of one repo can no longer start the same issue.
A start records a claim in a directory that every workspace shares, and a start of an issue that
another workspace has claimed fails, before the work of that workspace merges.

## Changes

- `start`, `update <name> in-progress`, and `new --state in-progress` record a claim in
  `sisyphus/claims/` of the jj repo directory or the git common directory.
- A start of an issue that another workspace has claimed fails, also for the same owner, and names
  the workspace, the owner, and the start time. `--take` moves the claim, with a warning.
- A claim ends when the issue leaves in-progress in its workspace. A claim whose workspace no longer
  has the issue in progress is stale: sisyphus ignores it, and a start replaces it with a warning.
- `list --ready` and `search --ready` leave out an open issue that another workspace has claimed.
- New command [[sisyphus-claims]] lists the claims with their status (`here`, `active`, or
  `stale`), and `--prune` removes the stale ones. The MCP tool `sisyphus_claims` runs it.
- The claim check runs before the warnings of the start, so a refused start prints only the error.
- AGENTS.md tells agents to run `sisyphus claims` and to take an issue with `sisyphus start`.
- [[sisyphus-start]], [[sisyphus-list]], [[commands]], the README, and [[sisyphus-mcp]] describe the
  claims. The decision is [[0024-share-claims-between-workspaces]].
- Tests use two working copies with the layout of `jj workspace add`. A manual test with two real jj
  workspaces gave the same result.
