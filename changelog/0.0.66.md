## Summary

The repo walk of `resolve`, `links`, `lint`, `new`, and `slug` skips the files that `.gitignore`
ignores, so a large ignored directory no longer slows them down.

## Changes

- New `cmd/sisyphus/repofiles.go`. In a git repo, one call of `git ls-files --others --ignored
  --exclude-standard --directory` gives the ignored paths, and the walk skips them, with every rule of
  git. Without git, the simple rules of the root `.gitignore` apply. `.git`, `.jj`, `bin`, `obj`, and
  `node_modules` are always skipped, as before.
- An ignored file is no longer a link target.
- [[sisyphus-resolve]] describes which files count. Tests cover both modes: a nested `.gitignore`,
  negation, a tracked file in an ignored directory, an untracked file, a deleted file, globs, paths
  from the root, and directory-only patterns.

| Generated repo | Command | Before | After |
|---|---|---|---|
| 1,000 issues + 100,000 ignored files, git | `resolve` | 137 ms | 10 ms |
| 1,000 issues + 100,000 ignored files, git | `links` | 176 ms | 14 ms |
| 1,000 issues + 100,000 ignored files, git | `lint` | 9,821 ms | 88 ms |
| 1,000 issues + 100,000 ignored files, no git | `resolve` | 140 ms | 9 ms |
| 1,000 issues + 100,000 ignored files, no git | `slug` | 80 ms | 8 ms |
| 20,000 issues, git, nothing ignored | `resolve` | 38 ms | 60 ms |
| 20,000 issues, git, nothing ignored | `links` | 48 ms | 74 ms |
