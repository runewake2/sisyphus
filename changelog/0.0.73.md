# 0.0.73

- Date: 2026-10-11
- Bookmark: samw/ai/ux-fixes
- Components: cli, sisyphus-mcp

## Summary

New commands `start`, `close`, and `abandon` for the most common state changes, and
`update -m` fills the Resolution section when an issue closes.

## Changes

- `sisyphus start <name>` is `update <name> in-progress`, with `--owner`, `--bookmark`, and
  `--workspace`.
- `sisyphus close <name> [-m "<text>"]` is `update <name> closed`, and `sisyphus abandon <name>
  [-m "<text>"]` is `update <name> closed --resolution abandoned`. `-m` fills the Resolution section
  in the same write, so the warning about an empty Resolution comes only without it.
- `update -m` (`--message`) fills the Resolution section; it needs the state `closed`.
  `sisyphus_update` has a `message` argument. There are no new MCP tools: `sisyphus_update` already
  names the states, and fewer tools help small models.
- The shortcuts call `updateIssue`, so the rules and warnings stay in one place. `editSection` and
  `update -m` share `setSection`, with the same checks.
- New pages [[sisyphus-start]], [[sisyphus-close]], and [[sisyphus-abandon]]; [[commands]] and
  [[sisyphus-update]] list them. Tests cover the three commands, `-m`, the warning without it,
  `-m` without `closed`, and a reopen after a mistaken close.
