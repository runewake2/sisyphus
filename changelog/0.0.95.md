# 0.0.95

- Date: 2026-10-11
- Bookmark: samw/ai/ux-fixes
- Components: cli, sisyphus-mcp, docs

## Summary

`sisyphus edit <name>` no longer starts an editor when no terminal is attached, and `sisyphus_edit`
with an empty `section` no longer starts the editor of the user from the MCP server. Before, both
waited for an editor that nobody could use. Found after [[0.0.84]].

## Changes

- `edit` with only a name fails at once when standard input is not a terminal, and tells the
  section form: `No terminal to run your editor in, ...`.
- `sisyphus_edit` with an empty `section` fails with `Give section: ...`, before it runs sisyphus.
- `sisyphus_edit` passes an empty `text` to sisyphus, which tells that the text is empty. Before,
  the empty text was dropped, and the error was about the number of arguments.
- Tests cover a missing terminal, an empty section, and an empty text. [[sisyphus-edit]] and
  [[sisyphus-mcp]] describe the behavior.
