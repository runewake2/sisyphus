# 0.0.46

- Date: 2026-10-11
- Bookmark: samw/ai/tracker-fixes-2
- Components: cli

## Summary

A metadata value with a comma is read back correctly, and a later metadata change no longer writes
a broken value to the file.

## Changes

- `parseMetadata` splits the metadata map only on commas outside quotes. Before, it split on every
  comma, so `{note: "x, y"}` read as `"x`, and the next `update --metadata` wrote that broken value
  back and lost the rest.
- A value can hold commas, colons, and escaped double quotes. What `formatMetadata` writes,
  `parseMetadata` reads back the same.
- [[sisyphus-new]] no longer says that a value cannot contain a comma.
- A test sends values with a comma, a colon, and quotes through `new`, `update`, and `show --json`.

None.
